# Aegis Audit — النسخة 0.8.0: محركات أمان AST وOSV وفحص التطبيق الموثق

Next.js 16 + React 19 + Node.js 24 + TypeScript. هذه أول مرحلة تشغيلية من التصميم المتفق عليه، وليست تنفيذًا كاملًا لكل محركات الأمن والمتصفح والمستودعات.

إذا كنت تستخدم النسخة السابقة، اتبع **[دليل التحديث UPGRADE_AR.md](./UPGRADE_AR.md)** للحفاظ على بياناتك وإعادة تشغيل العامل. التقارير القديمة تحتاج فحصًا جديدًا لإظهار النسب.

## التشغيل محليًا

تحتاج **Node.js 24 أو أحدث** وnpm. نفذ داخل مجلد المشروع:

```bash
npm ci
npm run browser:install
cp .env.example .env.local
npm run dev
```

على Windows PowerShell استخدم `Copy-Item .env.example .env.local` بدل أمر `cp` إن لزم.

افتح http://localhost:3000. يعمل عامل الفحص تلقائيًا مع dev. راقب إصدار العامل ونمط Chromium أو HTTP أعلى الصفحة. تفاصيل التحديث والحفاظ على البيانات في [UPGRADE_AR.md](UPGRADE_AR.md). لا تشغل عاملًا إضافيًا في التطوير.

لرؤية الواجهة والأدلة دون حساب: [http://localhost:3000/demo](http://localhost:3000/demo). بيانات العرض اصطناعية، ولا يرسل العرض أي طلب فحص أو AI. الإجراءات المتصلة تحتاج حسابًا حقيقيًا في النسخة المحلية.

## أول فحص حقيقي

1. أنشئ حسابًا بكلمة مرور 12 حرفًا على الأقل. لا توجد بيانات دخول افتراضية أو حسابات جاهزة.
2. أضف اسم المشروع ورابطه النهائي، دون query string أو بيانات اعتماد أو مسار يحتوي مفتاحًا سريًا.
3. أثبت ملكية الموقع بإحدى الطريقتين:
   - ملف `/.well-known/aegis-audit.txt` يحتوي الرمز المعروض فقط.
   - سجل DNS TXT باسم `_aegis-audit.your-domain.com` وقيمة `aegis-audit=YOUR_TOKEN`.
4. اضغط تحقق. التفويض صالح 7 أيام. النطاق الفرعي وorigin محددان ولا يمدد التفويض إلى خدمات خارجية.
5. اختر فحص الرابط وأقر بصلاحية الفحص. تابع المهام من الواجهة.
6. افتح المشكلة لرؤية الدليل وتوليد البرومبت، أو طلب شرح قصير من Ollama.

يجب أن يكون الموقع عامًا ويمكن الوصول له من سيرفر العامل. العناوين المحلية والشبكات الخاصة والمنافذ المخصصة محظورة. إذا أعاد الموقع التوجيه إلى `www` أو إلى HTTPS مختلف عن الرابط الأصلي، أدخل الرابط النهائي واعتمد نطاقه؛ هذه النسخة لا توسع التفويض تلقائيًا.

## ما تم تنفيذه

- تسجيل حساب ودخول وخروج، كلمات مرور scrypt مملحة، جلسات عشوائية مخزنة كبصمات، وcookies HttpOnly/SameSite.
- مشروعات خاصة بكل حساب، إثبات ملكية DNS أو ملف، وإزالة مشروع وتقاريره.
- مهام SQLite مستمرة عبر إعادة التشغيل، مع عامل مستقل وإلغاء وحدود استخدام.
- جلب HTTP مثبت على عنوان IP عام بعد فحص كل نتائج DNS، ورفض redirects خارج origin، وحد 2MB و15 ثانية لكل طلب.
- زحف موسع افتراضيًا حتى انتهاء الروابط المكتشفة، بحد حماية 5000 صفحة / ساعة، مع خيار فحص سريع منفصل. عند جاهزية Chromium يشغل JavaScript وaxe ويرصد طلبات GET العامة مع حدود موارد؛ وإلا يحلل HTML ومصادر JavaScript في وضع HTTP المعلن.
- قواعد فعلية لعنوان ووصف الصفحة وcanonical وh1 ولغة HTML وalt وأسماء الحقول وviewport ورؤوس CSP/HSTS/nosniff وحالات HTTP.
- كشف أنماط مختارة لمفاتيح مرتفعة الصلاحية وJWT يحمل `service_role`؛ إخفاء القيم وعدم اختبار استخدامها.
- جرد خدمات خارجية مثل Supabase مع تمييز مرجع مصدر عن طلب مرصود وعن طلب محظور.
- درجات مرجحة لكل محور ونسبة تغطية عددية منفصلة، وسجل لنتائج القواعد لكل صفحة (منفذة/غير متاحة/غير منطبقة)، مع فلترة وخطورة وأدلة وإعادة فحص وتصدير Markdown.
- مقارنة بمعرف المشكلة مع تقرير أقدم من نفس المشروع ونوع التقرير؛ عدم رصدها لا يثبت إصلاحها.
- برومبت إصلاح مباشر من بيانات التقرير، يعمل دون AI.
- موصل Ollama فعلي من Backend، مع timeouts وردود محدودة وتنقيح ومعالجة قطع الرد وقفل توليد على مستوى هذه المنصة.
- واجهة عربية RTL متجاوبة، وعرض توضيحي عام للقراءة فقط.

## Ollama

الإعدادات في `.env.example` مطابقة لملف المستخدم:

```dotenv
OLLAMA_BASE_URL=https://ollama-qa.apps.taqat.academy
OLLAMA_MODEL=qwen2.5:1.5b
```

يستدعي `src/lib/ai.ts` المسار `/api/chat` بـ`stream:false`، ويقرأ `message.content`. المخرجات 240 token والمهلة 90 ثانية. لا يدعم الإعداد الحالي الصور أو patch؛ يستخدم لشرح قصير فقط. **لم يتم اختبار السيرفر حيًا أو قياس دقة النموذج في هذه المهمة**؛ اختبارات الموصل تتحقق من العقد والحالات المحلية.

إذا أضفت مصادقة Bearer على بوابة Ollama، ضع `OLLAMA_API_KEY` على الخادم فقط. لا تستخدم مفتاح Resend لهذا الغرض. عند وجود مصادقة بصيغة أخرى يلزم تعديل headers في الموصل بعد معرفة البروتوكول.

قفل SQLite يمنع طلبَي توليد متزامنين داخل هذه المنصة، لكنه لا ينسق المشاريع الأخرى كـAegisQA. يلزم تنسيق مشترك أمام سيرفر النموذج عند تشغيل عدة عملاء.

## ما لم ينفذ بعد

| القدرة | الحالة |
|---|---|
| تشغيل JavaScript ورصد الشبكة وaxe | منفذ عند جاهزية Chromium، مع اختبار جاهزية عند الإقلاع |
| Lighthouse وINP الميداني | غير متاحين؛ LCP وCLS المختبريان يعرضان عند تسجيلهما في المتصفح |
| UX/UI | قواعد HTML وDOM وقياس التمدد الأفقي؛ لا تقييم جمالي بالصور ولا يتطلب نموذج رؤية |
| ظهور GEO/AEO الفعلي | توجد مؤشرات جاهزية HTML محلية؛ لا نقيس ظهور الموقع في محركات الإجابة |
| ربط GitHub والتحليل الثابت | متاح في 0.7.0، مستودع وفرع محددان وcommit مثبت |
| OSV لإصدارات npm المثبتة | متاح عند اختياره صراحة واتصال api.osv.dev؛ المصدر والتوكن لا يرسلان |
| Semgrep وتاريخ Git الكامل | غير منفذين؛ تحليل JS/TS المحلي يستخدم AST |
| API نشط، أدوار اختبار، سياسات RLS | لم تنفذ؛ لا يتم اختبار الخدمة المكتشفة تلقائيًا |
| تعديل كود أو branch أو Pull Request | غير مفعّل؛ يحتاج تكامل مستودع وعزل واختبارات |
| PostgreSQL/Redis وتعدد العمال/السيرفرات | SQLite لسيرفر واحد حاليًا |
| البريد واستعادة كلمة المرور والتحقق من البريد | غير متاحة في هذه المرحلة |
| عضويات الفرق وواجهة إنجليزية كاملة | غير متاحة بعد |
| الحذف التلقائي حسب مدد الاحتفاظ والنسخ الاحتياطي | سياسة التصميم فقط؛ يحتاج تنفيذ تشغيل قبل فتح عام واسع |

طريقة حساب النسب وأوزانها موثقة داخل اللوحة وفي UPGRADE_AR.md. هذه القيود ظاهرة في الواجهة والتقرير. لا نعتبر غياب نتيجة دليلًا على أمان الموقع. لا توجد اشتراكات أو دفع.

## البناء للإنتاج على سيرفر Node

```bash
npm ci
npm run typecheck
npm test
npm run build
npm run start:all
```

start:all يشغل الواجهة والعامل؛ أو استخدم عمليتين منفصلتين عبر systemd أو Docker. حدد `APP_ORIGIN` لعنوان التطبيق الحقيقي بما فيه HTTPS. حماية CSRF تقارن Origin بهذه القيمة. احفظ `DATA_DIR` على قرص دائم واجعل الوصول له محدودًا؛ يحتوي بيانات الحسابات والتقارير. ضع التطبيق خلف HTTPS وproxy يتيح زمن انتظار شرح AI، أو حوله لاحقًا لطابور AI مستقل. لا تنشر هذه النسخة كـstatic export أو داخل Cloudflare Worker.

`REGISTRATION_OPEN=false` يغلق إنشاء الحسابات الجديدة. لا يوجد تحقق بريد، لذا التسجيل المفتوح تجريبي ويحتاج مراقبة. قبل تسجيل عام واسع طبّق دورة حفظ/حذف ونسخ احتياطي ومراجعة نشر فعلية.

### Docker

```bash
cp .env.example .env.local
# عدل APP_ORIGIN إلى الرابط الذي ستفتحه من المتصفح
docker compose up --build -d
```

ملف `compose.yaml` يشغّل الواجهة والعامل على نفس volume لقاعدة SQLite. **لا تزد replicas العامل.** الصورة تستخدم مستخدم `node` غير root. ملفات Docker مرفقة لكن لم يبن Docker image داخل هذه البيئة.

## الاختبارات والتحقق

```bash
npm test
npm run typecheck
npm run build
```

الاختبارات تستخدم Node test runner وSQLite مؤقتة وHTML اصطناعي، وتشمل رفض الشبكات المحجوزة، DNS مختلطًا، عقد lookup المثبت، أسرار URL، إخفاء قيم المفاتيح، Supabase public/service-role، مصادقة وجلسات وعزل حسابين وCSRF، بوابة إثبات الملكية، إلغاء المهام، فشل الجمع، مسار عامل ناجح على fixture، رد Ollama المقطوع، ظهور خطأ داخل dialog، ومقارنة الفحوص زمنيًا.

`tests/api.test.ts` يختبر Route Handlers الحقيقية بـNextRequest دون فتح منفذ. يوجد أيضًا اختبار HTTP اختياري لسيرفر محلي مشغّل:

```bash
node tests/http-smoke.mjs
```

هذا ينشئ حسابين ومشروعًا وتقريرًا توضيحيًا للاختبار؛ استخدم قاعدة تجريبية. فحص HTTP الكامل من executor تعذر في بيئة العمل لأن عنوان المعاينة مرئي للمتصفح المعزول؛ لذلك لا ندعي نجاح ذلك السكريبت هنا. اختبارات Route Handlers واختبارات الوحدة وبناء Next.js تحققت محليًا، وتمت مراجعة صفحة الدخول والتقرير التوضيحي وتفاصيل المشكلة ورسالة الخطأ في المتصفح.

### ملاحظات مراجعة مؤجلة

1. تحديث الحالة الدوري قد يعيد شاشة الدخول عند انقطاع الاتصال؛ الجلسة الخادمية تبقى قائمة ويمكن إعادة التحميل.
2. طلبات الكتابة وWebSocket محظورة في المتصفح، لذلك قد لا تظهر بيانات التطبيقات المعتمدة عليها. مهلة كل صفحة محدودة وليست جلسة مستخدم مستمرة.
3. اختبار Chromium الفعلي تعذر في بيئة التنفيذ بسبب socket EPERM؛ يجب تشغيل `npm run test:browser` على السيرفر. اختبارات المنطق وTypeScript والبناء نجحت. Dockerfile مرفق ولم يُبن هنا.

## 0.3.1 — Ollama نصّي فقط

يرسل الخادم عنوان المشكلة والدليل والتوصية كنصوص فقط، ولا يرسل images أو لقطات شاشة أو مرفقات. محرك الفحص يعمل مستقلًا عن AI؛ ينفذ HTML/DOM/axe وقياسات المتصفح ويحسب الدرجات، ثم يستخدم Ollama لشرح الأدلة النصية. غياب دعم الصور لا يعطل هذه الفحوص. لا تتضمن النسخة تحليلًا جماليًا بالصور أو ادعاء رؤية من النموذج.

تحديث 0.3.2 يضيف مهل جمع 60 ثانية افتراضيًا وتشخيص مسار HTTP الفاشل وحفظ حالة الواجهة عند عطل التحديث. راجع UPGRADE_AR.md.

## مساحة العمل في 0.4.0

- **المشاريع:** إضافة الرابط والتحقق من الملكية.
- **مركز الفحص:** متابعة الخطوة الحالية، عدد الصفحات والقواعد وسجل أحداث العامل وتوقيتها. لا توجد نسبة تقدم تخمينية.
- **نتائج الفحص:** أقسام مستقلة للملخص والمشكلات وسجل الأدلة والتقرير والإصلاح.
- **سجل التقارير:** فتح فحوصك السابقة.
- **تقرير الفحص:** معاينة منظمة، تنزيل Markdown، وطباعة لحفظ PDF من المتصفح.
- **برومبت الإصلاح:** توليد لكل المشكلات أو حسب المحور والخطورة، مع نسخ وتنزيل؛ لا يحتاج AI.
- **المظهر:** زر فاتح/داكن أعلى الصفحة، اختيار النظام أولًا ثم حفظ الاختيار في المتصفح.

قوالب التقرير والبرومبت متاحة محليًا في العرض التوضيحي دون فحص حي أو استدعاء Ollama. تستخدم واجهات الحساب الحقيقي تفويض مالك التقرير. Ollama نصّي فقط للشرح الاختياري. سجلات الأحداث للفحوص الجديدة؛ السجل القديم يبقى كما هو.

## الزحف الموسع في 0.5.0

اختر فحص جديد ثم **زحف موسع — الافتراضي**. لا يعود يتوقف عند خمس صفحات. يقرأ robots.txt وخرائط sitemap/index وgzip داخل النطاق، ويتبع الروابط الداخلية من كل صفحة بما فيها الترقيم مثل ?page=2، وينظف معاملات التتبع ويزيل التكرار. قواعد Allow/Disallow المقروءة تطبق على صفحات الزحف ووجهات إعادة التوجيه. قراءة الروبوتات ليست ادعاء بتنفيذ كل امتدادات robots.txt؛ Crawl-delay غير مدعوم.

الحد الافتراضي5000 صفحة/ساعة من CRAWL_MAX_PAGES وCRAWL_MAX_DURATION_MS؛ يمكن تحديد حد الصفحات قبل البدء حتى10000. MAX_SCAN_PAGES=5 وMAX_SCAN_DURATION_MS في الإعدادات القديمة يؤثران فقط في وضع الفحص السريع. سقف اكتشاف داخلي10000–40000 رابط وميزانية اكتشاف30 ثانية/50 خريطة، وسجل آخر300 حدث؛ تظهر حدود الاكتشاف عند بلوغها. كل ذلك يمنع حلقات الروابط اللانهائية ولا يضمن حصر جميع صفحات الخادم.

تظهر أعداد المكتشف والمجموع والمتبقي والمستبعد والمتعذر والخرائط وسبب التوقف في الواجهة والتقرير. الزحف للموقع نفسه والصفحات العامة HTML فقط؛ لا يتجاوز تسجيل الدخول أو يزحف لنطاقات API الخارجية أو ينفذ POST. مسارات hash-only غير مدعومة؛ إظهار روابط مخفية يتوقف على DOM المتاح ومحرك المتصفح.

## تحسينات 0.5.1

حل الروابط بالنسبة إلى أول base[href] صالح في HTML؛ الروابط النسبية لخرائط متفرعة تحل مقابل عنوان الخريطة النهائي بعد إعادة التوجيه. الخريطة المعلنة التي ترجع404/410 توسم كاكتشاف غير مكتمل، بخلاف أسماء الخرائط الاختيارية غير الموجودة. اختبار اصطناعي122 صفحة بلا فشل أو متبقٍ؛75 اختبارًا إجماليًا، TypeScript والبناء ناجحة. لم يجر فحص حي جديد لموقع المستخدم.


## تحليل الأمان في 0.6.0

افتح **نتائج الفحص ← تحليل الأمان** أو اضغط بطاقة Security. ستجد 14 قاعدة أمان مخططة لكل صفحة (بعضها غير منطبق أو غير متاح)، مقسمة إلى سياسات المتصفح، النقل، الكوكيز، الفرونت، الأسرار، وAPI/Supabase. ترتبط النسب بسجل القواعد الفعلي، وليست نسبة سلامة الموقع.

- تحليل قيم CSP، بما فيها script-src-elem وscript-src-attr وnonce/hash وunsafe-eval؛ السياسات المتعددة تعرض للمراجعة بدل افتراض سياسة فعالة.
- HSTS بمدة موجبة، تقييد التضمين مع أولوية frame-ancestors على XFO، nosniff وReferrer-Policy.
- كوكيز الجلسة حسب نمط الاسم: Secure وHttpOnly، وSameSite=None، ومتطلبات __Host-/__Secure-. لا تحفظ الأسماء أو القيم في تفاصيل النتيجة.
- اتساق CORS على الصفحات وعلى استجابات fetch/XHR التي جمعها المتصفح؛ لا تضاف طلبات لفحص خدمات خارجية. wildcard مع credentials إعداد مرفوض من المتصفح، وليس إثبات تسريب.
- طريقة ووجهة نماذج كلمات المرور، المراجع النشطة عبر HTTP، وغياب SRI للسكريبتات الخارجية كمؤشر مراجعة.
- أنماط مفاتيح Supabase المرتفعة وGitHub وStripe وSlack وOpenAI، ومفاتيح PEM الخاصة وروابط قواعد بيانات تحمل بيانات اعتماد. لا تختبر صلاحيتها، وتخفى من التقرير والبرومبت. public anon/publishable ومعرف AWS منفرد ليسا سرًا إداريًا.

كل ملاحظة تتضمن الدليل، الخطورة، أساس الاستنتاج، طريقة الفحص، الأثر، المعالجة والتحقق والمراجع عند توفرها. زر **برومبت إصلاح الأمان** يحدد محور الأمان تلقائيًا؛ التفاصيل متاحة أيضًا في التقرير والبرومبت النصي دون Ollama.

اختبار BOLA/IDOR وتجاوز المصادقة والحقن والاستغلال الفعلي وRLS يحتاج نطاقًا مخولًا وحسابات اختبار؛ يعرض صراحة كغير مختبر. التحليل السلبي للرابط لا ينفذ اختراقًا نشطًا ولا يستخدم أسرارًا مكشوفة. أضيف فحص المصدر في 0.7.0 كما هو موضح أدناه.

أوقف العامل القديم وأعد التشغيل ثم أنشئ فحصًا جديدًا. التقارير السابقة لا تتحول إلى تحليل جديد بأثر رجعي. تحديث قاعدة البيانات إضافي دون حذف حساباتك أو مشاريعك.


## التحليل العميق وربط GitHub في 0.7.0

اقرأ [دليل ربط المستودع](docs/GITHUB_REPOSITORY_AR.md). أضف مشروعًا ثم افتح **المستودعات وGitHub**، واختر ريبو واحدًا وفرعًا، وأكمل التحقق من اتصال GitHub. يمكنك اختيار **فحص جديد ← التحليل العميق للمستودع**. المستودع العام لا يحتاج توكن؛ الخاص يحتاج Fine-grained token محدودًا لهذا الريبو مع Contents: Read-only. حد API العام قد لا يكفي لمشروع كبير؛ يمكن استعمال توكن قراءة محدود لمستودع عام أيضًا.

فحص الرابط مستقل عن فحص المستودع. الأول يحتاج إثبات النطاق، والثاني يحتاج إقرار صلاحية قراءة الريبو وتوكنًا صالحًا عندما يكون خاصًا. النتائج تعرض commit مثبتًا وملفًا وسطرًا، وعدد الملفات الفعلية وحدود الجمع. نماذج الكود غير الموثوقة لا تُشغّل ولا تثبت حزمها. القراءة والتحليل لا ينشئان PR أو تعديلًا تلقائيًا.

الافتراضي 1000 ملف مؤهل، حتى 3000 عبر REPOSITORY_MAX_FILES، و256KiB للملف و20MiB للنصوص و10 دقائق. symlinks وsubmodules والاعتماديات والبناء والملفات غير النصية مستبعدة. تجاوز الحد/شجرة GitHub المختصرة/الفشل ينتج تقريرًا جزئيًا واضحًا. لا تُفحص كل لغات البرمجة بمحلل متخصص؛ يظهر نقص التغطية صراحة. الأخطاء المستخرجة من الأنماط مؤشرات للمراجعة وليست إثبات استغلال.

تشفّر التوكنات AES-256-GCM بمفتاح محلي في `data/.repository-key` يُنشأ بصلاحية 0600، أو متغير `REPOSITORY_ENCRYPTION_KEY` من 64 حرف hex. احتفظ بمجلد البيانات كاملًا مع المفتاح في النسخ الاحتياطية، ولا تضفه إلى Git. شغّل الواجهة والعامل بنفس مستخدم النظام. مفتاح مختلف لا يفك توكنات قديمة؛ أعد الربط إذا فقد المفتاح. يستلزم إرسال التوكن HTTPS أو localhost للتطوير. يحتاج السيرفر اتصال DNS وHTTPS إلى api.github.com.


## محركات الأمان في 0.8.0

- تحليل JS/TS يستخدم TypeScript AST دون إخراج أو تشغيل كود، بما فيه الملفات التعريفية `.d.ts` والسكريبتات المضمّنة في HTML. لا يعتبر مجرد ذكر eval في تعليق أو نص استدعاءً فعليًا. أخطاء الصياغة لا تحتسب نجاحًا، وJSON يحلل نحويًا؛ اللغات الأخرى تبقى محدودة بالقواعد المعلنة.
- يمكن تفعيل **فحص ثغرات الاعتماديات OSV** عند بدء التحليل العميق. الخيار غير محدد افتراضيًا؛ اختياره يوافق على إرسال أسماء/إصدارات الحزم المثبتة فقط. يدعم package-lock.json وnpm-shrinkwrap.json بإصدارات npm lock 1/2/3، مع أسماء npm ونُسخ semver مثبتة. لا يشغّل npm install أو audit ولا يرسل ملفات المشروع أو توكن GitHub.
- حدود OSV: حتى 2000 إصدار فريد، 50 استعلامًا للدفعة، 50 قراءة تفاصيل، و500 نشرة معروضة، ضمن ميزانية المهمة. تجاوز الحدود أو صفحات استعلام غير مجمعة أو ملفات lock مفقودة من الجمع ينتج تغطية جزئية. النشرات المسحوبة لا تحتسب. إذا لم يحدد المصدر الخطورة تعرض كغير محددة ولا تخترع CVSS. إصدارات الإصلاح تعرض كما تذكرها النشرة، وليست ترقية آلية مضمونة.
- npm lock يمكن جمعه حتى 4MiB مع تحقق SHA؛ بقية المصادر حتى 256KiB، والإجمالي 20MiB. حد استجابة النقل 8MiB لقراءة ملفات lock الكبيرة؛ الافتراضي لبقية الطلبات 2MiB.
- خيار **فحص أمان التطبيق المنشور** يحتاج توثيق نطاق الموقع. يجمع HTTP من رابط المشروع نفسه ويطبق قواعد الاستجابة/HTML الأمنية، ولا يشغّل الريبو أو ينفذ استغلالًا أو اختبار تفويض/API/RLS نشطًا. يعاد التحقق من النطاق وحجز العامل وتلغى القراءة عند الإلغاء.
- قسم «محركات الأمان ونتائجها» يعرض وقت OSV، الإصدارات المستعلم عنها، النشرات، وحالة الموقع. سجل القواعد يميز «يحتاج إعدادًا» و«تعذر التنفيذ» و«خارج نطاق المحرك». التقارير القديمة لا تكتسب نتائج جديدة؛ ابدأ فحصًا جديدًا.

يحتاج السيرفر DNS وHTTPS إلى api.github.com وapi.osv.dev. تعذر الاتصال لا يحتسب نجاحًا. بيانات OSV تطابق إصدارات في نشرات عامة؛ لا تثبت استغلال التطبيق أو وصوله إلى المسار المتأثر. التفاصيل في [دليل محركات الأمان](docs/SECURITY_ENGINES_AR.md).

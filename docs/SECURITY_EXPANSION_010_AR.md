# محرك الأمان 0.10.0

أضيف تحليل فعلي للملفات المجموعة من GitHub إلى المحركات الموجودة، دون تنفيذ المستودع أو SQL، ودون إرسال بيانات جديدة إلى خدمات خارجية. كل نتيجة مرتبطة بالملف والسطر وcommit والدليل والطريقة والأثر وخطوات الإصلاح والتحقق.

## قواعد المصدر الجديدة

| القاعدة | ما ترصده | حدود الاستنتاج |
|---|---|---|
| repo.sql.parse | اكتمال تجزئة التعليقات والاقتباسات والأقواس وdollar-quoted bodies | ليست تحققًا كاملًا من صحة PostgreSQL |
| repo.sql.rls-declaration | CREATE TABLE وتعليمة تفعيل RLS لنفس الاسم في الملف | غياب التعليمة غير محسوم؛ قد توجد migrations أخرى |
| repo.rls-disabled | تعليمات ENABLE/DISABLE ROW LEVEL SECURITY | لا تثبت الحالة الحية أو ترتيب ملفات النشر |
| repo.sql.policy-open-read | سياسة CREATE POLICY بأدوار عامة/anon/authenticated وUSING دائم true أو افتراضي | مؤشر يحتاج مراجعة القصد وبقية السياسات؛ البيانات قد تكون عامة عمدًا |
| repo.sql.policy-open-write | شروط كتابة واسعة صريحة أو افتراضية أو موروثة؛ USING وWITH CHECK في UPDATE | لا يثبت استغلالًا أو صلاحيات GRANT أو بقية السياسات |
| repo.sql.grant-write | GRANT تعديل جدول إلى public/anon | منح العملية لا يثبت تجاوز RLS |
| repo.sql.grant-execute | GRANT EXECUTE/ALL لدالة أو procedure/routine إلى دور عام | لا يصنف صلاحية الدالة كصلاحية تعديل جدول |
| repo.sql.definer-search-path | SECURITY DEFINER دون SET search_path صريح | وجود الإعداد لا يثبت أن مساره ومخططاته موثوقة |
| repo.sql.definer-row-security | SET row_security = off/false/0 في تعريف SECURITY DEFINER | راجع دور المالك وصلاحياته؛ لا يشغّل الدالة |
| repo.supabase-verify-jwt | verify_jwt=false في قسم Edge Function ضمن supabase/config.toml | webhook عام قد يكون مقصودًا ويحتاج تحقق توقيع بديل |
| repo.jwt-expiry | استدعاء verify بخيار ignoreExpiration:true | فحص AST حرفي، لا يتتبع كل الدوال والواردات وتدفق البيانات |
| repo.jwt-none | algorithms تتضمن none في استدعاء verify | مؤشر إعداد خطر يحتاج مراجعة المكتبة والسياق |
| repo.cors-reflection | استدعاء cors مع origin:true وcredentials:true معًا | لا يثبت قراءة متصفح فعلية أو استغلالًا |
| repo.weak-hash | createHash('md5'/'sha1') | الاستخدام قد يكون checksum غير أمني؛ لا يفترض أنه تخزين كلمة مرور |

الأسرار والتحليل السابق وOSV ومصفوفة اختبار API تبقى متاحة. قواعد JWT/CORS والتجزئة الجديدة مبنية على AST لملفات JavaScript/TypeScript والصيغ المدعومة؛ لا تمثل محللًا متخصصًا لكل اللغات.

يتجاهل SQL التعليقات والنصوص وأجسام الدوال المقتبسة عند استخراج التعليمات الخارجية. يدعم true والأقواس البسيطة وتحويل boolean المباشر. يحد التحليل بـ60000 خطوة قراءة و250 ملاحظة SQL لكل ملف؛ الاقتباسات غير المكتملة وتجاوز الحدود لا تعتبر نجاحًا. TOML يفصل النصوص متعددة الأسطر عن الإعدادات؛ الصيغ غير المدعومة تظهر عند رصدها بدل افتراض تحقق JWT. لا يبني هذا الإصدار حالة قاعدة البيانات من كل ملفات migrations، ولا يحلل كل ALTER POLICY أو DDL الديناميكي أو PL/pgSQL أو كل تعبير منطقي. النجاحات تصف القاعدة المحددة فقط.

## لماذا قد ترى أربعة بنود وصفر طلبات API؟

إذا كان التقرير من محرك سابق، لا يتغير بعد تحديث الملفات. تعرض لوحة الأمان الآن تنبيه إصدار قديم وعدد نتائج SQL وعدد حالات API وعدد الطلبات المُحاوَلة. شغّل فحصًا جديدًا بعد إعادة تشغيل الخادم والعامل.

إذا لم تجهز اختبار API، فإن ربط GitHub يفحص المصدر فقط. من GitHub وAPI أدخل أصل API المستقل (حتى Supabase على نطاق منفصل)، وحسابين وموردين تجريبيين ووثّق الملكية ثم فعّل مصفوفة القراءة في الفحص العميق الجديد. راجع API_READ_MATRIX_AR.md. لا ترفع مفاتيح service_role ولا ترسل كلمات المرور في الدردشة. لا توجد طلبات كتابة أو حذف في هذا المحرك.

قد تبقى بنود نطاق أوسع غير منفذة، مثل اختبار كل عمليات API أو كل حالات SQL injection أو XSS أو منطق الأعمال. لا يحوّل نجاح فحص تعريف سياسة أو موردين تجريبيين تلك البنود إلى نجاح شامل. لا يمكن ضمان اكتشاف كل الثغرات آليًا.

## التحقق

160 اختبارًا اجتازت، ومنها 16 حالة تغطي الإضافات. أُعيد إنتاج ملاحظات المراجعة المستقلة واختبار إصلاحها: إلغاء v10، شروط UPDATE، منح تنفيذ الدوال وحدود الملاحظات، والثوابت المتكافئة، وإعداد row_security المقتبس. لا فحص حي لمشروع المستخدم ضمن هذا التحديث.

# Security scanner upgrade decisions

## Task 1 — preserve the 0.12.0 baseline

- The application and production scanner stay at 0.12.0. Scanner source base: `b2fcb2f`; accepted Task 0 documentation commit: `3fbbedc`. No scanner rules are upgraded in Task 1.
- Benchmark implementation lives only under `benchmark/`. No application or worker module imports it. `LocalReader` structurally implements `snapshot(branch, signal)` and `blob(file, signal)` from `GitHubReader`. It hashes the current local content, enforces size/count bounds, refuses symlinks and changed blobs, and never installs or executes scanned code.
- The seeded fixture is generated locally with deterministic, publicly marked, **fake-only** credentials. Its local Git repository has two commits and no remote. A fake credential deleted in commit two is an expected history miss for the snapshot-only 0.12.0 reader. No fixture is uploaded to GitHub.
- `BENCHMARK_MODE=1` is required for fixture generation, readers, the local HTTP transport and benchmark ownership setup. It is off by default and **always rejected with `NODE_ENV=production`**, including when explicitly set to `1`. This is a separate benchmark path, not an exception added to the production SSRF guard or application ownership enforcement. The CLI uses only an ephemeral in-memory database.
- The URL adapter allows explicit local fixture hosts only, checks and pins DNS, requires same-origin redirects, and bounds response size, redirects and request time. Its direct adapter measures current HTTP analysis only (root plus at most three same-origin scripts); it does **not** represent the full browser/crawler/authenticated worker. Application URL guards and normal ownership requirements stay active even in benchmark mode.
- Docker is required for Juice Shop, NodeGoat and DVWA. If the Docker server or target is unavailable, record `not_run`, with no quality score. Their `expected/*.json` arrays are **pending annotations**, not clean negative sets. Version-specific ground truth and container validation remain pending until the images can actually run; no recall/precision is claimed for them. The supplied Compose configuration has not been runtime-validated in this environment.
- The three clean fixtures are small synthetic Next.js-shaped projects, not third-party production codebases. Ground truth explicitly treats a non-security MD5 checksum and source-authored static HTML as benign. Both trigger current heuristic false positives. This measures those known benign contexts, not general population specificity.
- Quality matching is one-to-one on category and normalized `file:line`. Duplicate findings are false positives after the first match. This is a deliberately simple location benchmark, not proof of exploitability or semantic equivalence. URLs use paths; the targets namespace locations before aggregation.
- Dependency auditing uses the real existing OSV path only when `--osv-live` is supplied. It does not substitute canned responses. When OSV cannot complete, dependency quality is **unmeasured**, with its seeded expected item retained in the expected list but excluded from measured metrics; unknown category counters are null. Both target and aggregate metrics are saved, and the report is marked partial.
- Baseline output persists metadata, category, location, rule and severity only. No evidence, code excerpt or full credential is saved. A full fake-value check fails closed before writing. JSON is serialized structurally, not passed through free-text redaction that can invalidate its syntax.
- Durations measure scanner invocation (including OSV wait when requested), excluding fixture generation, dependency installation and container startup. An unattempted target has `durationMs: null`.

## Deferred to Task 7 — automatic API origin authorization

`runAutomaticApiHttp` currently probes discovered public API origins without **per-origin ownership verification**. Existing address/network restrictions are not per-origin authorization. Task 7 will restrict probes to **verified origins or same-origin only**. This behavior is documented here and **is not changed in Task 1**. The benchmark fixtures contain no external API origin, and the local benchmark reader adapter blocks external API HTTP requests rather than generating mock scan results.

## Task 1 follow-up rulings

- Dev/holdout allocation is frozen in sourced expected manifests and `expected.lock.json`. Default development runs omit holdout files; only explicit `--final` measurements report them. These cases were seen historically in Task 1, so this is a prospective holdout. Never tune detector rules against it.
- Expected files now cite official target sources or the authored `PLANTED-ISSUES.md`; no annotations are generated from actual detector output. Docker annotations remain pending rather than being inferred from HTTP observations.
- OSV exact error diagnostics are captured in the benchmark transport, without modifying production OSV detection/parser rules. `dependency-live-attempt.json` records a real DNS EAI_AGAIN failure. Offline fixtures use the same production OSV pipeline with a documented official advisory projection and a separate reference profile. Unknown requests fail closed. Unmeasured report counts and quality are null; scorer code is unchanged.
- Docker registry references are sourced digest pins. NodeGoat's official instructions build from source rather than publish a prebuilt image; no imaginary output digest is supplied. The script verifies the published v1.4 commit prefix, uses a digest-pinned Node base, and records the resolved full source commit and locally built image ID. This is a deliberate exception to requiring a prebuilt digest for every service. Docker runtime validation and image availability cannot be certified without Docker.

## Task 2 — canonical findings with compatibility

- Existing detector modules, rule IDs, severities, pass/fail checks, scoring weights and benchmark scoreRun stay unchanged. Normalization occurs at worker progress/final persistence and exposes canonical `normalizedFindings` plus `findingNormalization.toolStatus`; a legacy-compatible view is derived for the current UI.
- Numeric canonical confidence is calibrated separately from the UI's old high/medium labels. Normalizer suppression retains findings instead of deleting them. Failed or malformed tool output is incomplete rather than a clean empty result.
- Ruling: API access matrix identities are distinct canonical locations (`URL#case=stable-id`). Without this, two principals on one resource with identical evidence collapse; the existing API matrix regression test demonstrated 4 findings becoming 2. This preserves existing detector results, and does not tune a detector or use holdout evidence.
- The pre-normalizer offline dev reference is `reference-dev-offline.json`; the corresponding after-normalizer run is `task2-dev-offline.json`. Their category metrics match exactly. Final dev+holdout reporting is run only once implementation/review are finished; any holdout miss is reported without tuning.

## Task 2.5 — precision, evidence and sealed new negatives

- Only repo.weak-hash and repo.html-sink detection logic changes. The hash rule requires a bounded local security context; non-security checksums/cache/ETags are not medium findings. HTML constants and proven default sanitizer results are accepted, while unknown mutations/provenance/context remain dynamic. Filenames and benchmark target names never influence these decisions.
- Ruling: unresolved non-JavaScript HTML context is unavailable rather than using a regex to guess whether an injected value is constant/sanitized. This avoids a false clean/vulnerable classification at the cost of needing a specialized parser for those languages. Other language/rule behavior is unchanged.
- Ruling: imported sanitizer provenance/default options are recognized; configured/unknown sanitizer semantics remain conservative. Sanitized fragments are not promoted to safe in new concatenation/attribute contexts; sanitization must cover the complete dynamic HTML.
- The real scan boundary test demonstrated a raw progress-stage filename could contain a full secret. Progress stage strings in both workers are now redacted before persistence, alongside the already normalized results. Provider fingerprints are first4+last4, while PEM/database containers and unknown opaque credential values remain fully hidden. Generic value spans are protected atomically so a token-like prefix cannot expose a remaining password tail.
- Three new negative targets were authored and sealed after an initial code freeze. Independently reproduced development-review fixes were completed before final code sealing and before either scanner evaluated the new targets. No code or target input changed after final before/after measurements. Default dev runs do not load these targets. Their results are reported separately; no tuning was performed from them.
- The old Task 2 checkout and the new frozen code were measured on the same extended final set using offline OSV fixtures and identical source snapshots. The full-set code precision changes from 44.44% to 100%; on the previously published set it changes from 66.67% to 100%. All category recalls are unchanged. Offline dependency results remain fixture integration evidence, and Docker targets remain unrun.

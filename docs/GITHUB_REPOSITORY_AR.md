# ربط GitHub وتشغيل التحليل العميق

الربط متاح بدءًا من 0.7.0 والمحركات الجديدة بدءًا من 0.8.0، للقراءة والتحليل الثابت للكود. لا تحتاج إنشاء GitHub App أو منح صلاحية كتابة.

## الخطوات داخل منصتك

1. أضف مشروعًا من «المشاريع». يمكن تحليل الريبو قبل إثبات نطاق الموقع؛ فحص الرابط يبقى بحاجة لإثبات الملكية.
2. افتح «المستودعات وGitHub» من القائمة، ثم المشروع المطلوب.
3. أدخل الرابط بصيغة `https://github.com/OWNER/REPOSITORY`. لا تضع `/tree/main` أو توكنًا في الرابط.
4. أدخل الفرع، مثل `main` أو `develop`. تركه فارغًا يستخدم الفرع الافتراضي. الفرع الذي يحتوي `/` مدعوم.
5. للمستودع الخاص أدخل Fine-grained token؛ للعام يمكن تركه فارغًا. إقرار الصلاحية مطلوب، ثم اضغط «التحقق وربط المستودع».
6. اضغط «فحص المستودع»، أو «فحص جديد ← التحليل العميق للمستودع»، ثم أقر صلاحية القراءة وابدأ.
7. تابع الأحداث في «مركز الفحص»، وافتح النتائج لمراجعة commit والملفات والقواعد والخطورة. كل ملاحظة كود تعرض الملف والسطر ورابط المصدر المثبت.
8. أنشئ تقريرًا أو برومبتًا من النتائج. برومبت الأمان يحصر الملاحظات الأمنية. لا يُرسل الكود الكامل تلقائيًا إلى AI.

## إنشاء توكن قراءة محدد

في GitHub: Settings ← Developer settings ← Personal access tokens ← Fine-grained tokens ← Generate new token.

- Resource owner: صاحب المستودع أو المؤسسة.
- Repository access: **Only select repositories** ثم الريبو المطلوب فقط.
- Repository permissions: **Contents: Read-only**. Metadata للقراءة تلقائية.
- اختر انتهاء صلاحية مناسبًا. بعض المؤسسات تتطلب الموافقة على التوكن.
- أدخله في الحقل داخل منصتك. لا تضفه إلى `.env` الخاص بالمشروع المفحوص ولا ترسله في المحادثة.

لا يمكن للتطبيق إثبات أن توكنًا منحه المستخدم محصور بريبو واحد؛ التطبيق نفسه يطلب ملفات الريبو المختار فقط. ينصح بإنشاء توكن مخصص بأقل الصلاحيات. قبول الاتصال لا يضمن أن حد API سيكفي لكل الملفات.

## البيانات والحماية

يحفظ التوكن مشفرًا على السيرفر ويربط التشفير بهوية الحساب والمشروع والاتصال. المتصفح يستلم حالة وجود توكن فقط؛ لا يستلمه مجددًا. حقل التوكن يمسح بعد الربط. إعادة الربط بدون توكن تزيل بيانات الدخول السابقة؛ لا تعمل للمستودع الخاص.

المفتاح الافتراضي ينشأ في `data/.repository-key`؛ احتفظ بمجلد البيانات كاملًا و`.env.local` عند التحديث. يمكن للمشغل ضبط `REPOSITORY_ENCRYPTION_KEY` كقيمة hex من 32 بايت (64 حرفًا) قبل أول ربط. تغيير المفتاح يتطلب إعادة ربط التوكنات القديمة. شغّل الواجهة والعامل بنفس المستخدم، واستخدم HTTPS عند النشر؛ التوكن لا يقبل على HTTP خارجي. localhost متاح للتطوير.

المصدر لا يثبت أو ينفذ، ولا تتبع symlinks/submodules أو تعليمات داخل الملفات. لا يحفظ المصدر الكامل في التقرير. القيم المطابقة للأسرار لا تعرض أو تختبر. إلغاء الفحص يوقف القراءة الجارية؛ فك الربط يلغي فحوص الريبو النشطة. ألغِ الفحص قبل تغيير الريبو أو الفرع. إلغاء الربط لا يلغي التوكن في GitHub؛ يمكن إلغاؤه من إعدادات GitHub.

## النطاق والحدود

كل تشغيل يحل الفرع إلى commit ثم يقرأ الشجرة والملفات بتعريفاتها SHA؛ لا يخلط نسخًا إذا تحرك الفرع أثناء الفحص. الافتراضي 1000 ملف مؤهل، 256KiB للمصدر و4MiB لملف npm lock، 20MiB نصوص، و10 دقائق. الملفات التي تتجاوز الحجم أو ليست UTF-8 تستبعد بوضوح ويستمر الجمع. تُستبعد مجلدات الاعتماديات والبناء والأنواع غير المدعومة. توقف الحد/المهلة أو فشل GitHub يعطي نتيجة جزئية أو فاشلة، دون احتساب نجاح وهمي.

القواعد الحالية أنماط ثابتة: أسرار مرتفعة الصلاحية، تنفيذ ديناميكي، مواضع إدخال HTML، استعلامات وأوامر نظام مبنية بالنصوص، تجاوز TLS، متغيرات عامة تحمل أسماء أسرار، تعليمات تعطيل RLS، وبعض إعدادات package.json. يستخدم JS/TS محلل AST بدءًا من 0.8.0، ويضاف OSV اختياريًا لإصدارات npm المثبتة. لا تحليل تدفق شامل أو تاريخ Git أو Semgrep. بعض اللغات تتلقى قواعد مشتركة فقط ويظهر نقص التغطية. وجود مؤشر لا يثبت استغلاله وغيابه لا يثبت الأمان.

فحص الموقع وSEO/GEO والوصول والأداء يكون من «فحص الرابط». لا تعطي ملفات المستودع وحدها قياسات متصفح أو تأكيدًا لحالة قاعدة Supabase الحية.

## إذا تعذر الربط

- راجع اسم الريبو والفرع والوصول للمستودع الخاص وContents: Read-only وتاريخ انتهاء التوكن وموافقة المؤسسة.
- حد GitHub للمستخدم غير الموثق قد يوقف مستودعًا كبيرًا؛ استعمل توكن قراءة محدودًا أو أعد الفحص بعد تجدد الحد.
- وفّر DNS واتصال HTTPS على 443 إلى `api.github.com` من السيرفر. لا يجري تحويل الاتصال أو التوكن تلقائيًا إلى مضيف آخر.
- إذا نقلت الريبو/غيرت اسمه فحدّث الرابط؛ التحويلات لا تتبع تلقائيًا.
- إذا بقي الفحص في الانتظار فأوقف العامل القديم ثم شغّل `npm run dev` من مجلد 0.7.0؛ لا يتطلب فحص الكود Chromium.

## تشغيل فحوص الأمان الجديدة

في «فحص جديد ← التحليل العميق» اختر OSV صراحة؛ الافتراضي غير محدد لمنع إرسال بيانات الاعتماديات دون اختيارك. الخدمة تستقبل أسماء الحزم وإصداراتها فقط. تحتاج package-lock.json أو npm-shrinkwrap.json في الفرع، واتصال HTTPS من سيرفرك إلى api.osv.dev. لا تحتاج توكن OSV.

لفحص HTTP الخاص بالتطبيق، أكمل إثبات النطاق من المشاريع ثم اختر «فحص أمان التطبيق المنشور». لا يشغّل هذا الخيار المستودع ولا يختبر حسابات المستخدمين أو Supabase RLS الحية. راجع [دليل المحركات](SECURITY_ENGINES_AR.md) للنتائج والحدود.

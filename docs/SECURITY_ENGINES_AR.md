# تشغيل محركات الأمان — 0.8.0

## لماذا كان يظهر «غير متاح»؟

قراءة GitHub وحدها لا تشغل تطبيقًا أو قاعدة نشرات. أضيف الآن محرك AST محلي، واستعلام OSV اختياري، وفحص HTTP للتطبيق الموثق. كل محرك يسجل حالته بدل افتراض النجاح.

## تشغيل فحص جديد

1. احتفظ بربط المستودع الحالي؛ لا تحتاج صلاحيات GitHub أوسع.
2. تأكد أن الفرع يحتوي package-lock.json أو npm-shrinkwrap.json. المحرك يحتاج إصدارات مثبتة؛ package.json ذي نطاقات مثل ^1.0.0 لا يكفي لمطابقة دقيقة.
3. اختر «فحص جديد ← التحليل العميق».
4. حدد «فحص ثغرات الاعتماديات OSV». هذا يوافق على إرسال أسماء وإصدارات الحزم فقط إلى api.osv.dev؛ لا كود أو توكن أو عناوين resolved. الخيار غير محدد في كل فحص جديد حتى تختاره.
5. إذا أردت فحص التطبيق المنشور، أكمل إثبات النطاق من المشاريع ثم حدد خياره. يستخدم رابط المشروع الموثق نفسه ولا يرسل توكن GitHub إلى الموقع.
6. ابدأ وتابع الأحداث. عند الانتهاء افتح «محركات الأمان ونتائجها» ضمن الملخص أو تحليل الأمان، وسجل القواعد والنشرات المطابقة.

## ما الذي ينفذ؟

| المحرك | المدخل | النتيجة الفعلية |
|---|---|---|
| AST | JS/TS والسكريبتات المضمّنة | عقد الاستدعاء/الخصائص مع الملف والسطر، دون تشغيل أو تحليل تدفق كامل |
| JSON | ملفات JSON المجموعة | صحة الصياغة؛ لا يثبت صحة كل إعداد بالمخطط |
| قواعد المصادر | الصيغ المدعومة | أسرار ومؤشرات أمان محددة؛ لا إثبات استغلال |
| OSV | أسماء npm وإصدارات semver المثبتة | معرف النشرة، aliases ومنها CVE إن توفر، الخطورة المنشورة إن وجدت، وإصدارات إصلاح تذكرها النشرة |
| HTTP للتطبيق | الرابط العام الموثق | رؤوس الأمان وHTML والكوكيز/CORS المرصودة؛ لا اختبار تفويض نشط |

## حالات النتائج

- «نُفّذ»: اكتملت الاستعلامات في النطاق المجمع. لا يعني حصر كل ملفات أو ثغرات المشروع.
- «نُفّذ جزئيًا»: حد جمع، lockfile لم يجمع، ترقيم لم يكتمل، أو تعذر بعض التفاصيل. تعرض النتائج التي جُمعت مع حدودها.
- «يحتاج تفعيلًا/إعدادًا»: لم تحدد المحرك، أو غاب ملف lock مناسب، أو يلزم توثيق النطاق.
- «تعذر التنفيذ»: فشل اتصال/استجابة/مهلة؛ لا يتحول هذا إلى فحص ناجح.
- «خارج نطاق المحرك»: لغة أو فحص لا يملك هذا المحرك تحليلًا له. لا يختفي فقط لتجميل الدرجة.

OSV يدعم هنا npm lock بإصدارات 1/2/3؛ يتجاوز حزم link أو إصدارات غير ثابتة أو مصادر غير registry.npmjs.org ويبين نقص التغطية. الاستعلام حتى 2000 إصدار فريد، دفعات 50، تفاصيل حتى 50 نشرة، عرض حتى 500 نشرة. ترقيم OSV الإضافي لا يفترض اكتماله. لا تختلق خطورة عند غياب بيانات المصدر؛ المعلومة غير المحددة موسومة بذلك. إصدارات الإصلاح ليست قائمة ترقيات آلية مضمونة لكل نطاق.

ملفات npm lock حتى 4MiB، بقية المصادر 256KiB، النصوص الإجمالية 20MiB، ضمن حد الملفات والوقت. لا تثبيت حزم أو تشغيل postinstall أو برنامج من المستودع. AST يقرأ الصياغة فقط؛ لا يفحص كل المكتبات أو يتتبع البيانات عبر المشروع بالكامل.

## متطلبات السيرفر

Node.js24، تثبيت الاعتماديات بالـlock المرفق، وعامل 0.8.0. AST يستخدم TypeScript ضمن اعتماديات التشغيل. OSV يحتاج DNS وHTTPS على 443 إلى api.osv.dev؛ قراءة المستودع تحتاج api.github.com. لا ترسل بيانات مستخدمين أو حسابات اختبار عبر استعلام OSV. لا يعمل الفحص من المعاينة الاصطناعية؛ سجل دخولك واستخدم مشروعك.

## ما بقي خارج النطاق؟

اختبار IDOR/BOLA وتجاوز المصادقة، واستغلال الحقن، وSupabase RLS الحية بحسابات متعددة، وتشغيل المستودع نفسه. فحص HTTP لا يحل محلها. يلزم لها بيئة staging وحسابات وتعريفات API وأدوات تفويض مخصصة؛ لا يعلن التطبيق تنفيذها دون أدلة. وجود CVE لحزمة مثبتة لا يثبت أن تطبيقك يصل للمسار المتأثر، وغياب نشرة لا يثبت الأمان.

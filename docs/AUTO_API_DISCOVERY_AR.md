# اكتشاف API تلقائيًا — 0.11.0

> تحديث: ابتداءً من 0.12 يتبع الاكتشاف فحص HEAD/OPTIONS تلقائي بلا اعتمادات. عبارة عدم إرسال طلبات إضافية أدناه تصف إصدار 0.11 فقط. راجع AUTOMATIC_API_HTTP_AR.md للسلوك الحالي.

لا تحتاج إدخال رابط API أو تعبئة إعداد حسابين لتشغيل الاكتشاف. بمجرد تشغيل تحليل عميق، يقرأ المحرك المصادر المجموعة ويستخرج الأصول والمسارات تلقائيًا، بما فيها Supabase على نطاق منفصل. وعند فحص الرابط يدمج مراجع HTML وJavaScript وطلبات API المرصودة في المتصفح عند توفره.

## المصادر المدعومة

- استدعاءات fetch وaxios وcreateClient التي تحتوي رابطًا نصيًا مباشرًا.
- إعدادات apiUrl وapiOrigin وendpoint وbaseURL وSupabase URL في متغيرات JavaScript/TypeScript وJSON وملفات إعداد مدعومة.
- مراجع Supabase النصية في JavaScript حتى عند تصغير أسماء المتغيرات في الحزم.
- مسارات نسبية مباشرة مثل `/api/profile`، تحل مقابل أصل مشروع الموقع، لا أصل GitHub.
- سكريبتات المتصفح التي جُمعت بنجاح، وطلبات fetch/XHR المرصودة فعليًا.

لا تنفذ أمثلة الكود أو التعليقات. تقرأ المراجع حرفيًا ولا تثبت أن كل مرجع مستخدم وقت التشغيل. الروابط المركبة ديناميكيًا أو الموجودة فقط في متغيرات بيئة غير متاحة قد لا تكتشف من المصدر؛ طلبات المتصفح العادية قد تكشفها إن حدثت خلال نافذة الرصد. لا يمكن جلب قيمة سرية أو حساب مستخدم غير موجود في المدخلات.

## النتائج داخل المنصة

- بطاقة اكتشاف تلقائي: عدد الأصول والمصادر، وعدد المراجع المستبعدة، وبيان الجرد الجزئي عند بلوغ الحدود.
- قسم الخدمات وAPI: الأصل والنوع ومصدر الاكتشاف والمسارات. يدمج المسارات للوجهة نفسها دون فقد رصد الطلب الفعلي.
- سجل الفحوص: دليل اكتشاف لكل أصل، وفحص استخدام HTTPS في المرجع. التحذير عن HTTP مؤشر من المصدر، وليس اختبار شهادة TLS أو إثبات إرسال بيانات إنتاج.
- التقرير Markdown يتضمن جرد الخدمات وحالة الاكتشاف. البحث وتنزيل السجل JSON متاحان.

قيمة origin وحدها ليست إثباتًا بأن خدمة قاعدة بيانات مكشوفة. قواعد المصدر والأسرار والسياسات تعمل كما سبق، ولا تستخدم المفاتيح المكتشفة لإرسال طلبات. الاكتشاف لا يولّد هويات دخول، ولا يقرأ سجلات العملاء، ولا يحوّل RLS أو اختبار عزل غير منفذ إلى نجاح.

## هل أحتاج تفعيل مربع الاختيار؟

لا. الاكتشاف التلقائي مفعّل دائمًا. مربع «اختبار عزل بحسابين — اختياري ومتقدم» خاص بتجربة وصول حسابين وزائر إلى موارد تجريبية فعلية. إعداد الحسابين يبقى اختياريًا لذلك الاختبار فقط. الفحص العادي والعميق لا يتوقفان على تعبئته.

## ضوابط وحدود

لا تُرسل طلبات جديدة إلى عناوين API المكتشفة تلقائيًا. تُحلل المصادر التي جمعها الفحص المأذون وطلبات المتصفح المعتادة التي تسمح بها سياسة الموارد. لا تحفظ query values أو fragments أو التوكنات من الاستدعاء؛ الروابط ذات username/password أو الوجهات الخاصة أو المسارات التي تبدو سرية تستبعد. المصدر غير مكتمل أو المثال قد يقود إلى مرجع غير منشور؛ تحقق من حالة observed_reference مقابل observed_request.

حد مصدر الاكتشاف النصي 512KiB و100 مرشح و20 أصلًا لكل مصدر، والجرد المدمج حتى 64 أصلًا و20 مسارًا لكل أصل. JSON له حد traversal إضافي. تصل الحدود والاستبعادات إلى التقرير، وتستمر معالجة الملفات اللاحقة حتى عند بلوغ حد في ملف سابق. تظل حدود جمع المستودع والزحف والمتصفح الأوسع كما هي.

لا يتطلب هذا الإصدار اشتراكًا أو إضافة خدمة خارجية. Ollama يستقبل نصوص التقرير فقط وفق الإعداد السابق.

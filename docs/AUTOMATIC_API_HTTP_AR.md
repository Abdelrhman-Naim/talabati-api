# فحص API تلقائي فعلي — 0.12.0

## المشكلة التي عولجت

كانت النسخة السابقة تكتشف المراجع فقط، وتضيف ست حالات اختبار حسابين إلى السجل حتى إن لم يطلبها المستخدم. لذلك ظهر صفر طلبات API مع بنود تحتاج إعدادًا رغم تفعيل الاكتشاف. بدءًا من 0.12، الاكتشاف يتبعه فحص HTTP تلقائي، ومصفوفة الحسابين لا تضيف حالات أو تخفض التغطية ما لم تُطلب صراحة. لا يعاد تفسير التقارير القديمة؛ ابدأ فحصًا جديدًا بعد التحديث.

## السلوك التلقائي

1. استخرج أصل API من المستودع أو المصادر والطلبات المجموعة كما في 0.11.
2. اختر حتى ثمانية أصول عامة مصنفة API/Supabase، دون روابط تحمل بيانات اعتماد.
3. أرسل HEAD ثم OPTIONS إلى `/` فقط لكل أصل؛ في Supabase ذي النطاق `.supabase.co` يستخدم `/rest/v1/` بدل مسارات الجداول.
4. HEAD يجمع حالة HTTP ورؤوس الاستجابة. تُفحص منه HSTS وnosniff وأعلام الكوكيز المناسبة، دون اعتبار 401 أو 403 إثباتًا على عزل البيانات.
5. OPTIONS يرسل Origin تجريبيًا غير موثوق وAccess-Control-Request-Method: GET. لا يرسل GET نفسه. يرصد إقران allow-credentials مع الأصل التجريبي، أو تركيب wildcard مع credentials؛ النتائج مؤشرات إعداد وليست إثبات قراءة سجلات.
6. سجّل الطريقة والمسار والهوية غير المعتمدة ووقت التنفيذ وHTTP والزمن والحجم والمرصود. لا تحفظ أجسام الاستجابة أو التوكنات.

لا يحتاج الفحص التلقائي حسابين أو مفتاح API أو إعدادًا يدويًا. يعمل في فحص الرابط والتحليل العميق. لا يُعاد استخدام أي مفتاح من الكود، ولا يُقرأ مورد مستخدمين، ولا تُجرّب معرفات أو تُنشأ حسابات ولا تُرسل عمليات كتابة.

## الدقة والحدود

- نجاح HEAD يعني استلام استجابة فقط. 401/403/404 لا تعني نجاح اختبار المصادقة أو RLS، ولا تُصنّف تلقائيًا كثغرة.
- إذا لم يوفر مسار البيانات الوصفية preflight ناجحًا، يظهر CORS غير محسوم مع حالة HTTP الفعلية؛ لا يطلب حسابات لإخفاء فشل الاتصال.
- لا تتبع التحويلات. الروابط الخاصة محظورة، وكل DNS يُفحص ويثبت قبل الاتصال. لا تُرسل Authorization أو Cookie أو apikey أو جسم طلب.
- حد المرحلة 20 ثانية، ومهلة الطلب حتى 4 ثوانٍ بما فيها انتظار DNS، وإلغاء المهمة يوقف الطلب الجاري. تجاوز الوقت أو الاتصال المحجوب يظهر بنتيجته الحقيقية. الاستجابة محدودة بـ4KiB.
- تدعم معالجة النقل HEAD والاستجابات دون جسم 204/304 حتى لو حملت Content-Encoding؛ لا يُحاول فك ضغط جسم غير موجود.
- اختبار عزل حسابين يبقى قدرة اختيارية منفصلة تتطلب هويات وموارد تجريبية؛ عند عدم طلبه يظهر خارج السجل والدرجة والتغطية.
- أزيلت البنود العامة غير المنفذة security.api-auth/security.supabase-rls من قواعد HTTP التلقائية. لا يعني ذلك فحص صلاحياتها؛ حدودها واضحة في قسم القدرات خارج الطلب. مصفوفة الحسابين المطلوبة تظل تسجل نتائجها الست الفعلية أو سبب تعذرها.

## أين تظهر النتائج؟

مركز الأمان يعرض عدد طلبات HTTP المُحاوَلة والاستجابات المكتملة للفحص العادي والعميق. سجل الفحوص يبين كل طلب ونتيجته، والتقرير Markdown وJSON يحفظان ذلك. عدّاد السجل يخص المحور/المجموعة المعروضة؛ HEAD قاعدة جمع استجابة تقنية، بينما OPTIONS وقواعد الرؤوس أمنية، لذا قد يختلف عدد الطلبات في مجموعة أمنية مصفاة عن إجمالي المرحلة.

هذا التحديث لا يدعي اختبار كل API أو صلاحيات كل جدول. يفحص بيانات HTTP الوصفية للنطاقات المكتشفة، وقواعد المصدر والسياسات والأسرار تعمل بصورة منفصلة.

## التحقق

185 اختبارًا اجتازت مع TypeScript والبناء الإنتاجي. اختبارات النقل استخدمت استجابات محلية محقونة ولم تختبر API مشروع المستخدم الحي. المراجعة المستقلة راجعت حدود الطلبات والاعتمادات والتوثيق؛ أصلحت ملاحظة HEAD المضغوط وانتظار DNS ووضوح ملخص فحص الرابط.
